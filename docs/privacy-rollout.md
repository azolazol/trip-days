# Trip Days 개인정보 변경 적용 — 2026-10-17

## 공개 프런트엔드
모든 도시 공통: privacy.html, 방문통계 선택/철회, 지도 클릭 후 연결, 문의 선택 이메일 동의, 개인정보 삭제 요청 유형 및 문의 삭제 버튼.
Google Analytics와 광고 SDK는 설치하지 않았습니다. 미래 광고 동의를 미리 수집하지 않습니다.

## Google Apps Script 서버 적용 (GitHub 커밋만으로 배포되지 않음)
1. 기존 Trip Days Backend 프로젝트에서 Code.gs, Bridge.html, appsscript.json을 이 저장소의 apps-script 파일로 업데이트합니다. SPREADSHEET_ID, SITE_ORIGIN 등 기존 속성을 유지합니다.
2. 운영자 표시, 개인정보 처리방침, Google 사용 계약·처리위탁·국외이전 안내를 실제 계정 조건에 맞춰 검토합니다. `FEEDBACK_TO`에 운영자 수신 이메일을 설정합니다. 이 값은 공개 코드에 넣지 않습니다.
3. 검토 후 Script Properties에 `PRIVACY_REVIEWED_VERSION=2026-10-17`을 설정합니다. 개인정보 처리위탁·국외이전 세부사항이 아직 확정되지 않았다면 이 속성을 설정하지 않습니다.
4. `setupPrivacy()`를 1회 실행하고 권한 승인합니다. Feedback 시트를 준비하고 매일 만료 데이터를 정리하는 트리거를 설치합니다. 이 단계는 보관기간을 지난 기존 문의·통계 기록도 삭제합니다.
5. 배포 관리 → 기존 웹 앱 배포 수정 → 새 버전으로 배포합니다. 기존 /exec URL을 유지합니다. 새 배포 주소가 생기면 config.js도 갱신해야 합니다.
6. 공개 사이트를 새로고침합니다. /api/privacy-status가 해당 버전과 feedbackReady/analyticsReady를 반환한 경우에만 문의·통계가 활성화됩니다.
7. 익명 테스트: 통계 미동의 상태의 Visitors 행 증가 없음, 동의 후 증가, 철회 후 해당 식별정보 삭제를 확인합니다. 동의하지 않은 사용자의 필수 기능은 유지됩니다.
8. 문의 테스트: 선택 이메일 무입력 접수, 입력 시 별도 동의 필요, 접수번호, 비공개 Feedback 저장, 알림 메일에 내용/이메일 없음, 동일 브라우저 삭제를 확인합니다. 테스트 메일 발송은 실제 운영자 수신으로 진행됩니다.

## 운영·삭제
- Feedback: 접수 후 최대 90일. 처리 목적을 달성하면 즉시 해당 행을 삭제하거나 스크립트에서 `resolveFeedback('접수번호')`를 호출합니다. 90일은 법정 일률 기간이 아닌 서비스 운영정책입니다.
- Visitors: 마지막 방문 후 최대 90일. 결과 표시는 ‘오늘 / 최근 90일 방문자’입니다. 각 사이트 방문 기록은 통계 전용 토큰을 사용하며 내 장소 소유권 토큰과 분리합니다.
- 하루 1회 purgeExpiredPrivacy 트리거 실패 알림을 확인합니다. 서버 요청 때도 정리를 수행합니다. 트리거가 삭제되면 신규 접수/집계가 차단됩니다.
- 기존 구현이 이미 문의 본문을 이메일로 발송했다면 과거 이메일/수동 사본은 자동삭제 대상이 아닙니다. 삭제 요청·보관기한에 맞춰 별도로 정리해야 합니다.
- Sheets 행 삭제는 공급자의 버전 이력·백업까지 즉시 영구삭제한다는 뜻이 아닙니다. 해당 서비스의 보관정책을 확인하고 운영 안내에 반영합니다.
- 기존 Visitors 식별값은 종전 내 장소 토큰의 해시입니다. 새 통계 토큰으로 철회해도 과거 토큰 기록과 자동 연결되지 않으며, 종전 기록은 만료 정리 또는 운영자 처리 대상입니다.
- 개인정보 관련 요청과 별도로 약국 환자·처방정보는 사용하지 않습니다.

## 검증 범위
Node tests/check.cjs, tests/feedback.cjs, tests/privacy.cjs로 일정/권한/동의/비식별 알림/삭제 격리를 검사합니다. 실제 Apps Script 배포와 트리거 설치는 별도 확인해야 합니다.
